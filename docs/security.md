# 安全边界与威胁模型

## 信任边界

- Control、本机 SQLite、部署主密钥和用户管理的 TLS 代理位于可信中心环境。单个 Control 进程是授权和派发决策点。
- Windows 便携中心端只注册 Control 虚拟服务账号。Control 监听 `0.0.0.0:19090`，SQLite 不监听网络端口，首次运行为 19090 添加入站规则；管理员必须把该规则收紧到可信代理来源。解压目录及旁置 `data` 禁用 ACL 继承，只允许 Administrators、SYSTEM 和 Control 服务 SID 修改。服务命令行只出现配置路径，不出现主密钥。
- Linux/macOS 离线镜像必须先通过发布方提供的 SHA-256 或签名校验并选择原生平台。预构建 Compose 通过绝对 `MASTER_KEY_FILE` 路径让 Control 在 `app_data` 卷中以权限 `0600`、无覆盖方式创建随机部署主密钥；后续启动复用该文件，显式 `MASTER_KEY` 与文件不一致时失败关闭，链接或非普通密钥文件也被拒绝。预构建 Compose 默认把明文 Control 端口只发布到 `127.0.0.1`，使用只读根文件系统和 `no-new-privileges`。PID 1 仅在启动最前段以 root 和 `CHOWN/FOWNER/SETGID/SETUID` 初始化三个固定卷目录、采用 Docker Socket 的组 ID，随后不可逆降为 `panel`；正常服务阶段有效 capabilities 为空。
- 固定 Compose 把宿主 `/var/run/docker.sock` 读写挂载给 Control 以支持网页自更新。Docker API 能创建特权容器和挂载任意宿主路径，因此该 Socket 实际授予宿主 root 级控制权；容器降权、只读根文件系统和 capabilities 限制不能把已攻陷的 Control 与宿主隔离。只有全局所有者的交互式会话可以发起升级，接口仍要求 CSRF 和幂等键，但这不能降低 Control 进程自身被攻陷后的影响。宿主只能运行受信任的 Control 镜像，不得在同一 Docker daemon 上混放需要与面板隔离的工作负载，Docker daemon、部署目录和卷的访问权只能授予中心管理员。
- 容器在线升级包限制为 1 GiB、一个 `l4d2panel/control:offline` 镜像和当前宿主架构；归档拒绝链接/穿越/重复路径并校验全部内容寻址 blob，产品、版本和目标镜像 ID 在停服前后重复核对。正式语义版本禁止降级或切回无序开发标签；开发构建可替换为其他开发构建或转入正式版本。SHA-256 和 OCI 内容摘要只验证完整性，不证明发布者身份；管理员仍必须在上传前校验发布方独立提供的校验值或签名。升级 Worker 只接收内部固定子命令和持久 job spec，不接受用户 Shell、任意容器参数或宿主路径；容器重建请求由允许列表重新生成，不转发 Inspect 中的任意 HostConfig、网络 IPAM、入口点或命令。它在停服后快照 SQLite、WAL/SHM 与主密钥；新容器未通过 `/readyz` 时，只持久化退出码、OOM 标志和最多 500 字符的尾部诊断，诊断会移除控制字符并遮盖常见密码、令牌、Cookie、授权头和主密钥字段，然后恢复快照和旧容器。Docker Socket 本身仍然是上述不可消除的高权限边界。
- Compose 不安装 Docker、不修改宿主防火墙；管理员显式改为外部监听时必须自行限制为只允许可信 HTTPS 代理访问。
- Agent 是节点上唯一拥有实例文件与受管游戏进程操作权的组件。面板管理员不会因此获得操作系统 Shell；Agent 只接受固定任务类型和经过校验的参数。
- RCON 可执行游戏命令，因此属于高权限游戏接口。命令通过权限检查，敏感形态在审计/任务视图中脱敏，明文命令只以部署主密钥加密后排队。
- VPK、SMX、SourceMod 插件和原生扩展是不可信内容。特别是 `.dll/.so` 会在游戏进程权限内执行，只允许管理员安装，第三方原生包还必须显式确认风险。
- 当前同一节点的 Agent 和全部 srcds 进程共用一个低权限服务账号，没有每实例 OS 身份或进程沙箱。PathGuard 约束的是 Agent 接口，不能阻止已在游戏进程内执行的恶意原生扩展读取该账号可访问的其他实例数据；相互不信任的实例必须使用不同主机或额外的 OS 级隔离。
- 节点本身被攻陷后，Agent 凭据、该节点实例和本地备份均不再可信；节点隔离不是对恶意主机管理员的沙箱。

## 用户认证和授权

- 密码使用 Argon2id；登录按“来源 IP”和“来源 IP + 规范化用户名”分别限速，5 分钟窗口内组合上限 8 次、IP 总上限 32 次。
- 首次启动不要求环境变量携带引导密码。本机 `setup-key issue` 生成带固定前缀的 32 字节随机密钥，标准输出只显示一次，数据库只保存 SHA-256 摘要；初始化前重新签发会原子替换摘要。仅在数据库没有用户时，`/setup` 可用短期 HttpOnly/SameSite=Strict 引导 Cookie、独立 CSRF 令牌和专用限速校验密钥；SQLite 立即事务内重新校验摘要、创建 `admin` 根所有者并删除摘要，确保并发提交只有一个成功。密钥以 Argon2id 保存为初始密码，创建后入口立即失效。
- 浏览器会话 Cookie 为 HttpOnly、SameSite=Strict；生产环境必须启用 Secure。所有非安全方法还需匹配 `X-CSRF-Token`。
- TOTP 秘钥用 `MASTER_KEY` 加密。启用 TOTP 时返回 10 个恢复码且只显示一次；数据库只保存加域哈希，每个恢复码通过事务原子消费一次。
- API Token 以 `l4d2p_` 开头，明文只在创建响应返回，数据库只保存 SHA-256 摘要。Token 必须有未来过期时间，权限为 `read/operate/manage`，可限定到节点或实例，且不能超出创建者绑定。
- Bearer API Token 不受 CSRF 影响，但不能调用注销、TOTP、API Token 管理或团队账号管理等要求交互式会话的接口；即使由所有者签发，也不能执行 `root_security` 操作。
- 团队账号列表、创建、密码重置、禁用和角色绑定修改全部要求全局所有者的交互式会话。新账号没有管理员指定的初始密码：Control 生成含 192 位随机量、24 小时有效且只返回一次的 `l4d2p_once_` 凭据，SQLite 只保存 SHA-256 摘要。第一次成功登录会在立即事务中销毁凭据并签发最长 10 分钟的受限激活会话；除查看自身状态、注销和设置新密码外，所有 REST 与事件接口都由后端拒绝。正式密码以 Argon2id 保存，激活会原子轮换普通会话；重新签发会撤销旧凭据和激活会话，正常账号不能重新签发。更改密码、禁用账号或替换角色绑定会撤销目标账号的所有现有会话和 API Token。引导所有者不可禁用/降级，系统始终要求至少一个启用的全局所有者。

## RBAC

角色是创建绑定时的一键权限预设，从高到低为：

- 所有者：全部资源以及根安全设置，可管理其他所有者。
- 管理员：节点和实例管理、包安装及通知渠道；不能查看或管理团队账号，也不能修改根安全设置。
- 操作员：日常值班运维预设，在观察者只读权限之上增加实例配置、启停/重启、切换地图、任务详情/取消以及查看、导入、分配、校验和删除地图。预设不授予踢出、封禁、解除封禁、聊天广播、任意 RCON、文件内容读取/写入/删除、备份下载/创建/恢复或计划任务管理；文件类只保留目录浏览，备份与计划类只保留查看备份、查看计划和日志读取。实例范围的地图删除仍只能删除当前账号自己导入的地图；管理员也可按具体权限集合显式调整这些能力。
- 观察者：只读。

每条绑定还持久化具体权限集合；选择角色会填入预设，之后可逐项增减，授权时以具体权限为准。多条匹配绑定取权限并集，不支持显式拒绝。所有者的全局 `root_security` 预设不可裁剪或下放；任何节点级非查看权限必须同时带有 `nodes.read`，任何实例级非查看权限必须同时带有 `instances.read`。绑定可以是全局、某节点或某实例。节点绑定自动覆盖该节点内实例；实例绑定通常不授予节点级管理，唯一例外是显式下放的共享地图权限：`maps.read/import/verify/delete` 只映射到所选实例所在节点的地图库，且实例范围的 `maps.delete` 只能删除当前账号自己导入的地图。地图库和任务列表响应会向具备相应读取权限的主体附带上传者或操作发起人的当前显示名称用于归属识别，但不暴露用户名或团队账号清单。全局审计与来源地址另需 `audit.read_global`，普通 `audit.read` 只用于已授权资源。

具体权限彼此不会因为角色等级或名称而隐式推出。`players.broadcast` 只允许经过长度限制的安全聊天广播，`rcon.execute` 允许提交任意受支持的 RCON 命令，两者独立且互不包含。节点发现的专用轮询只依赖同节点的 `nodes.discover`，并只返回固定结构的发现结果，不借用通用任务正文权限。`jobs.details` 可凭已知任务 ID 独立读取目标范围内经脱敏的正文与结果，但任务列表仍需 `jobs.read`。`audit.read_global` 可独立读取全局审计与来源地址，普通 `audit.read` 只读取已授权资源且隐藏来源地址。创建计划任务同时需要目标实例的 `schedules.manage` 和被计划动作本身的权限：`start/stop/restart/backup/broadcast` 分别需要 `instances.start`、`instances.stop`、`instances.restart`、`backups.create`、`players.broadcast`；读取、启停或删除既有计划还分别受 `schedules.read`/`schedules.manage` 约束。地图分配是另一个有意的复合授权：主体必须通过节点绑定或同节点实例绑定获得 `maps.read`，并对目标实例具备 `maps.assign`。实例范围只允许向该实例分配或取消地图，不会借此管理同节点其他实例。

Control 在列表、单资源、任务、指标、通知、审计和 WebSocket 事件上都按具体权限与资源范围执行过滤，而不是只依赖前端隐藏按钮。在线事件流使用当前主体快照做内存过滤；登出、Token 吊销、账号禁用、密码或绑定变更会递增授权代际并在通知后的下一帧前重验，另每 1 秒从数据库兜底重验数据库提交到进程内通知之间的极短调度窗口、到期和进程外变更。历史或未知且没有明确节点/实例归属的事件对受限主体一律隐藏。

任务正文和结果只有对该任务目标节点/实例具备 `jobs.details` 权限时才返回；只有 `jobs.read` 的绑定不会因为用户在其他资源拥有操作权限而绕过脱敏。加密秘密字段在任何角色的任务视图中都不会返回。

## 节点身份和传输

- 注册令牌由 CSPRNG 生成、数据库只存摘要、有效期 1 分钟至 7 天且成功使用后立即消费；管理员创建令牌时填写的节点显示名称随令牌保存并在消费时成为节点名称，避免受 Agent 主机名覆盖。
- 节点长期凭据数据库只存摘要，可由管理员轮换或随节点删除吊销。轮换会断开旧连接并让节点离线，管理员需安全更新节点配置。删除节点会在单个立即事务中清理中心端关联资源及资源级权限绑定、使浏览器授权快照失效并断开 Agent；审计和事件保留不受影响，节点主机文件和进程不会被远程删除。
- Agent 默认通过 HTTPS/WSS 主动出站连接且不开放面板管理端口。为同机和可信隔离局域网部署提供的明文兼容模式只接受 `localhost`、回环、RFC 1918 IPv4、IPv6 ULA 或链路本地 IP，不解析明文 DNS 主机名，也拒绝公网 HTTP/WS。该模式不提供机密性或完整性：一次性注册令牌、长期 Bearer 节点凭据、任务和结果都可能被同网段监听者读取或篡改，部署者必须把它限制在受控网络；公网及不完全可信网络仍必须使用 TLS。
- Control 在持久化或发布前批量验证心跳、指标和日志中的每个实例都属于当前 WSS 节点；未知或跨节点实例会拒绝整条消息。成功归属按连接缓存 2 秒且上限 1024 项，同一实例并发 miss 合并；失败不缓存，实例删除成功后立即清除缓存，所以数据库查询量受实例数和 TTL 限制而不随日志行数增长。`job_update` 必须匹配任务节点和实例，嵌套结果中的 `instance_id` 也不能指向其他实例。入站心跳、指标、日志、进度和终态结果分别设有消息/批量上限，并校验状态、数值、时间窗口与日志流；重复或高频进度会被丢弃/合并，终态不会被节流。
- Agent 配置原子写入；Unix 权限为 0600。便携入口在首次网络请求前重新写入并收紧同目录配置，注册成功后从配置中删除一次性令牌；已经注册的配置拒绝用启动参数切换到另一中心端。无子命令便携模式使用启动者身份且不假设服务沙箱。显式 `install --config` 才允许改变系统服务状态：Linux 只在 systemd 主机上提权、创建无登录 `l4d2panel` 账号并拒绝根目录、包含 Agent 二进制的宽泛目录和链接；Windows 经 UAC 注册 `NT SERVICE\l4d2panel-agent` 虚拟账号并限制 ACL，目录只给 SYSTEM/Administrators 可继承的完全控制及固定服务 SID 可继承的修改权限，配置和二进制使用非继承文件权限，确保服务后来创建的日志和状态仍可由提升后的管理员维护。幂等安装会重新同步这些 ACL，并可接管已经由 Agent 登记但服务账号不可写的游戏安装；路径来自 Agent 数据目录中的无秘密本地登记，并在提权后再次要求绝对、非宽泛、无链接、不是程序父目录且根目录直属位置存在平台固定普通 `srcds`，然后才批量变更属主/ACL。Linux 递归改属主前预检整棵树并拒绝特殊文件和嵌套挂载点；普通硬链接仍拒绝，唯一例外是地图注册表能列出该 inode 的全部对象/实例路径且登记路径数与实际 `nlink` 完全一致，任何未知链接都会使安装失败。远程任务只能登记结构正确的路径并执行低权限写探测，不能调用提权接管。安装和后续控制会核对同名服务仍指向当前二进制、配置及固定账号，拒绝接管外部服务。部署者必须把二进制、`agent.yaml` 和 `data` 放在非共享永久目录。升级只允许在进程停止后用已验证的同平台二进制替换程序文件，不触碰配置和数据，并保留前一版本供回滚；系统服务和前台模式使用同一旁置升级流程，不存在必需的安装脚本层。
- 用户管理的 HTTPS 代理必须提供证书、HTTP 到 HTTPS 跳转和 HSTS；Control 设置 CSP、frame deny、MIME sniffing 禁止和权限策略。只有配置的精确可信代理网段可影响客户端 IP。

## 秘密和任务数据

- 显式 `MASTER_KEY` 或 `MASTER_KEY_FILE` 的内容必须解码为正好 32 字节，用于加密 TOTP、中心端保存的 RCON 凭据、SMTP/Webhook 秘密，以及任务中的 RCON 命令、外部实例旧 RCON 密码、带查询参数的下载 URL、QQ 闪传分享链接、备份/恢复归档定位符、文件/包上传正文、日志查询关键字和传输正文。
- 计划任务的 payload 以普通 JSON 保存，因此创建接口只允许 `start/stop/restart/backup/broadcast`，并按动作复制已知字段；任意 RCON、游戏安装维护、URL、文件正文和包安装等秘密/高风险动作不能进入计划表。创建时除 `schedules.manage` 外还要检查目标动作本身的具体权限，安全广播不会因此获得任意 RCON 权限。
- RCON 与 SMTP/Webhook 密钥不会通过普通资源列表返回。API Token、恢复码、注册令牌和节点凭据只存摘要。实例 RCON 凭据可以留空；Control 不把它写入游戏文件，管理员必须在 `server.cfg` 中配置匹配值。
- 文件内容与日志/备份分块虽然经过 Control，但不以明文持久化。日志搜索结果和下载块在读取后从任务结果删除；再次读取返回 `410 Gone`。
- 跨节点备份上传要求顺序 offset、每块 SHA-256、末块整包大小/SHA-256 和分块必填幂等键。单块解码上限 1 MiB、单会话上限 20 GiB且 Control 会话默认 24 小时，每个成功块只续期 24 小时；正文在 Control 任务中以主密钥加密并于终态清除，只暂存在目标 Agent 的受限数据目录。分块状态使用独立的 `backups.restore` 专用端点，复核实例、会话和固定任务类型后只暴露 `job_id/status`，不要求或泄漏通用任务读取/详情；失败或取消的块必须换新幂等键后重试。Agent 默认限制为每节点 32 个会话和 64 GiB 预约总量。首次可信分块在节点上传互斥内先用临时文件、刷盘和原子改名写入严格 JSON、权限 `0600` 的预约 sidecar，后续分块必须与其中的整包大小/SHA-256 完全一致；旧版无 sidecar 的 `.part/.zip` 在可信续传升级前按 20 GiB 保守预约。上限同时核算所有会话 `expected_size`、sidecar/临时元数据和未知常规文件，磁盘检查覆盖全部未完成预约并保留 5 GiB 余量，检查失败发生在任何 `.part` 变更前。Agent 对无活动未完成 `.part` 使用约 25 小时保留期，完整 `.zip` 使用 48 小时保留期；完整校验与每次恢复尝试都会续租完整会话。完成、续租、删除和清理按 UUID 将 `.part/.zip`、sidecar 和原子临时文件成组协调，覆盖 Control 失败后续期的 24 小时无重传重试窗口且不会遗留不计费文件。会话/API 不返回 staging 路径，过期上传由两端清理；只有完整 ready 会话可进入现有停服、检查点和归档验证恢复流程。同一恢复键始终重放原任务；失败或取消后会话续期 24 小时，新键可无重传重试。
- Agent 的受限数据目录 journal 会保留任务终态和原始结果，直到 Control 已成功持久化、应用并发布对应事件后返回 `job_ack`；ACK 丢失时结果保留并在重连后重放，收到 ACK 后原子删除。因此 Agent 数据目录与本地节点备份一样属于敏感节点数据，必须维持服务账号专用权限。
- `MASTER_KEY` 丢失会导致已加密秘密不可恢复；密钥泄露会破坏这些秘密的机密性。应在密码管理器中备份密钥，轮换前需要专门迁移流程，不能直接替换环境变量。
- Windows 便携版固定使用 EXE 旁置的本机 SQLite。`portable unregister` 刻意保留数据库、WAL、SHM 和主密钥；`portable purge` 要求精确确认短语并只删除已验证部署根下的 `data`。升级包受到条目数、展开大小、路径、设备名、ADS、符号链接/重解析点、清单和 SHA-256 约束，但清单未签名，不能证明发布者身份。无序开发构建可以替换为其他开发构建或正式版本；有序语义版本禁止降级或切回开发标签。升级先停服并快照旧程序、配置和 SQLite；迁移或健康检查失败时自动完整回滚，回滚失败则保持停服并保留材料。升级 journal 只保存版本、阶段、时间、包摘要和脱敏错误，服务恢复后才将这些非秘密字段镜像进 SQLite 任务、审计和事件。

## 文件、归档与下载

- 自定义 SteamCMD 是节点管理权限下的显式信任决定。Control 只发送绝对路径；Agent 固定接受 Windows `steamcmd.exe` 或 Linux `steamcmd.sh`/`steamcmd`，逐组件拒绝符号链接和重解析点，拒绝游戏根目录内路径，以固定 `+quit` 自检成功后才原子激活。后续游戏维护仍只使用固定 SteamCMD 参数数组和收敛环境，不接受调用方可执行文件、Shell、参数或环境变量。节点离线时不能预存待执行路径。
- 托管 SteamCMD 只从固定 Valve HTTPS 地址下载到 Agent 数据目录，归档限制条目、展开大小、路径和文件类型；修复采用 staging、备份和失败回滚。切换到自定义路径不会修改或删除自定义文件。

- `PathGuard` 先做词法归一化，再验证真实路径仍在配置根内；符号链接和 Windows 重解析点不能用来逃逸。文件管理的列举、读取、原子写入和删除还使用目录句柄相对操作消除检查后替换窗口：Linux 以 `openat2/openat`、`O_NOFOLLOW` 和受限解析逐级打开，Windows 以 `NtCreateFile`、`RootDirectory`、`OBJ_DONT_REPARSE` 和不共享删除的句柄固定目录对象；旧内核回退也从 `/` 逐级 no-follow 打开，不退化为再次按绝对路径访问。相同原语用于外部 ZIP/tar、Workshop、单文件 VPK/SMX/native 安装、版本快照/回退、模组启停移动、备份恢复 overlay/extras 清理和旧版遗留配置清理；内容在提交前验证精确大小及可用的 SHA-256。Windows 另拒绝 ADS、设备名和特殊 Win32 路径组件。启动参数以数组传给 `exec`，不经 Shell；`-tickrate` 只允许出现一次且必须带 1–1000 的整数值。
- 备份创建仍会对实例内目录做只读路径遍历，Agent 专属 staging/备份保留策略也会按自身数据目录清理名称；这些路径不承担向实例落盘。不受信任归档不能在 staging 创建链接，所有后续实例 mutation 会再次由句柄边界约束。同一节点的 Agent 与游戏进程共享低权限服务账号，因此本设计不是抵抗该账号下任意恶意本机进程的每实例 OS 沙箱；不互信的原生插件应部署到不同主机或服务账号。
- 安装发现只在配置的实例根内做有界、只读、非链接扫描，返回根索引与相对路径；它不会枚举任意系统目录。扫描到的外部运行进程必须在导入和受控重启时再次核对可执行路径，不能仅凭 PID 接管。
- 运行环境的新建或导入接口只接受节点本机绝对路径，不要求它位于配置的实例根下。Agent 在登记、维护、启动和恢复前逐组件拒绝符号链接/Windows 重解析点；登记成功后以该绝对目录本身作为实例根，所有文件、归档和包操作仍只能使用安全相对路径访问其内部。添加现有目录只确认平台对应的 `srcds` 是普通非链接文件，不把这一步描述为 Steam 完整性校验。创建实例绑定已有安装时仍要求 Control 与 Agent 都已登记的同一 ready 安装 ID 和绝对路径；直接提交绝对路径时，Control 创建 pending 临时记录并以仅在内部传递、必须等于目标安装 ID 的标记限制该记录只能被当前创建流程绑定，其他 pending 安装继续返回冲突。Agent 随后的导入任务仍会独立验证并登记路径。`absolute_game_paths` 能力阻止 Control 把此类任务派给旧 Agent。未绑定安装可由具备 `environments.manage` 的交互式会话删除：`record` 只删除 Control/Agent 登记并保留文件；`files` 永久删除整个登记目录。后者通过 `game_installation_delete_v1` 能力门控，Agent 重新匹配安装 ID 与绝对路径，拒绝仍包含已登记实例、其他游戏安装或活动 SteamCMD 的父目录，以及文件系统根、Agent 数据/实例根/可执行目录和任何含链接或 Windows 重解析点的目录，将核验后的目录原子改名隔离后才递归删除。Control 仅在 Agent 成功结果与请求路径、模式一致后删除中心记录。
- 文件 API 只开放 `cfg/addons/logs` 白名单目录；目录列表需要实例 `read`，正文读取及写/删需要 `operate`。浏览器正文单文件上限 8 MiB，不允许递归删除目录。模组扫描需要 `packages.install` 和 `package_scan_v1`，Control/Agent 都不接受调用方路径：Agent 只扫描固定 `left4dead2/addons` 的直属 `.vpk` 普通文件，跳过子目录、链接/重解析点及 `l4d2panel-map-*`，最多处理 1000 个候选。每个候选通过句柄相对 no-follow 打开并校验 512 MiB 上限、v1/v2 结构、节区边界、逐项 CRC、大小和 SHA-256；只有有效且尚未按路径登记的文件才投影为普通 VPK 包，扫描不会改写或删除文件。停用已纳管的 VPK/SMX 必须先停止实例：网页会禁用入口，Control 在排队事务中拒绝非 `stopped` 状态，Agent 在 no-follow 移动前再按本地进程状态校验，不能通过直接 API 调用绕过。模组入口的 QQ 闪传导入需要 `packages.install`，目标由 Control 与 Agent 双重固定为 `left4dead2/addons`；Agent 在数据目录中完整暂存分享，最多接受 10000 个分享/归档项、2 GiB 下载和展开数据、1000 个 VPK、3 层 ZIP/7Z/RAR 嵌套并保留至少 1 GiB 空闲。归档读取按魔数识别并拒绝加密包、分卷 RAR、链接、特殊路径、100:1 以上压缩比和任何非 VPK 普通文件；VPK 必须使用 `.vpk` 扩展并通过 512 MiB、v1/v2 结构、节区边界及逐项 CRC 校验。所有输入通过后才用实例目录句柄和不覆盖的唯一名称提交，失败会清理暂存且不留下部分包；成功结果逐个投影为普通 VPK 包记录。元数据与文件客户端分别固定到 `qfile.qq.com` 和 `multimedia.qfile.qq.com`，禁用代理和重定向，在每次拨号时拒绝私网、环回、链路本地、组播与 CGNAT 地址。通用安全分段下载器默认并发 4，QQ 闪传请求 8，但节点级 HTTP 正文并发硬限制为 8；每段严格匹配 `206`、`Content-Range`、长度与总大小。身份校验优先使用强 ETag，通用来源无强 ETag 时使用 Last-Modified；QQ CDN 的 Last-Modified 会随大区间偏移变化，所以仅 QQ 固定集成以分享元数据的不可变 `physical_id` 绑定对象并忽略该不可靠时间头。包删除另需 `packages.delete`，Agent 只接受包记录中的标准 VPK/SMX 路径并在删除前复核 SHA-256；历史快照定位符必须仍位于该实例的哈希命名 Agent 数据目录。普通文件 API 继续拒绝 `.vpk` 等加载关键格式。普通正文写入的 SHA-256 前置条件用于检测并发覆盖。
- 插件/模组包的浏览器本机上传上限为 100 MiB；Control 在加密入库前流式校验 Base64 和解码大小，Agent 解密接收后再次执行同一原始大小限制。智能插件只接受按魔数确认的 ZIP、7Z 和单卷 RAR，拒绝链接、加密/分卷归档、危险路径、Windows 设备名、ADS、超限条目和解压炸弹；识别阶段不触碰实例。安装阶段不信任浏览器预览，必须重新解压并核对预览指纹，重新检查最终覆盖路径、面板登记所有权、no-follow 普通文件状态和 SHA-256。只有未被其他包登记的现有磁盘文件能在逐项确认后接管，并保存删除时恢复的基线；已登记路径始终拒绝跨包覆盖。整套 SourceMod/Metamod 同样在写入前检查固定组件目录和跨包所有权，并把成功安装的逐文件哈希投影为精确卸载清单；SourceMod 的 `admins_simple.ini` 是显式保护例外，存在时不覆盖，且无论由首次安装创建还是原本存在都不进入卸载清单。智能插件编辑只开放清单内非入口的 CFG/TXT/SP/INC/NUT 有界 UTF-8 正文；Control 要求数据库哈希前置条件，Agent 再复核本地清单和磁盘哈希，原子替换后同步清单，清单提交失败会恢复原文件。该放宽不改变普通文件 API 的 8 MiB 上限，也不改变备份、升级包、QQ 闪传或 URL 下载限制。
- 结构化配置会在 Control 和 Agent 两端拒绝 CVar 映射中的 `rcon_password`、`sv_password`；密码必须由管理员直接维护在 `server.cfg`，中心端 RCON 字段只保存匹配的加密连接凭据。启动参数只包含固定的 `+exec server.cfg`，不会携带密码，也不允许调用者改换被执行的配置文件。读取实例时仅返回 `rcon_configured` 布尔状态，绝不回读密码或密文；空密码不把成功运行的游戏进程标记为异常。
- 普通 ZIP/TAR 解包限制文件数、单文件/展开总大小和压缩比，拒绝绝对路径、`..`、设备文件和链接。整套组件卸载只接受安装后持久化的有界逐文件清单，要求停服并再次核对每个普通文件的固定目录、大小和 SHA-256；不做递归目录删除，失败从预先创建的检查点恢复。无清单的旧记录拒绝卸载，SourceMod 尚存在时拒绝删除 Metamod。地图导入另以固定纯 Go ZIP/7Z/RAR 读取器按魔数处理最多三层嵌套，统一限制 20 GiB 下载、40 GiB 展开与 VPK 虚拟内容、100000 项、20 GiB 单项、100:1 压缩比并保留 5 GiB 空闲；加密包、分卷、绝对路径、`..`、设备文件、链接、Windows 设备名/ADS 和重解析点全部拒绝。直接上传、URL 安装及回退的 VPK v1/v2 验证目录树大小/项数、安全 UTF-8 相对路径、节区边界、终止符、重复/重叠条目和逐项 CRC32；单文件安装拒绝引用外部分卷，地图读取器额外支持受边界校验的外部数据块。v2 公钥/签名区当前只验证结构长度，不执行密码学签名验证，因此不能据此信任发布者身份。官方 SourceMod/Metamod 原生包先信任稳定页选出的 AlliedModders GitHub 仓库、GitHub Release 资产域名及项目自己的 `sm.alliedmods.net`/`mms.alliedmods.net`。Agent 另从固定 `api.github.com` 发布接口取得所选资产的 SHA-256 与大小；只有元数据完整匹配时，才在官方地址均失败后依次尝试固定白名单 `gh-proxy.com`、`ghfast.top`、`ghproxy.net`，并对每次下载（包括官方源）强制复核该摘要和大小。摘要缺失或 API 不可达时不启用第三方镜像；镜像目标必须仍是两个固定 AlliedModders 仓库，调用方不能提供镜像、代理域名或重定向目标。Workshop 下载候选只根据 SteamCMD 固定目录中的 `.vpk`/`*_legacy.bin` 文件名发现，不验证 VPK 内容；它仍须是非链接普通文件，并在 no-follow 复制时核对来源大小和 SHA-256。地图导入内部同名路径按稳定后者覆盖；地图、普通模组、Workshop 和历史版本之间的跨包虚拟路径重叠由 L4D2 挂载顺序决定，不由面板阻断。
- 地图对象以 SHA-256 寻址，只在配置的每卷 `map_roots` 下发布。实例目标只能是 `left4dead2/addons/workshop/l4d2panel-map-<map-id>-<part>.vpk`；普通文件、QQ 模组、包安装、切换和回退入口均拒绝该保留前缀。Linux 以 dirfd + `linkat`，Windows 使用根目录句柄 + NT `FileLinkInformation` 建立硬链接，随后复核卷身份、文件身份、大小和哈希；符号链接/Junction/no-follow 边界没有放宽。运行中分配的热更新只允许代码内固定的 `sm_update_vpk` RCON 命令，不接受用户提供的命令或参数；Control 仅在派发时解密并附加实例 RCON 凭据，未配置时安全跳过并要求管理员在游戏内手动输入 `!update_vpk`。mission 元数据按 1 MiB 文档、16 层嵌套和 20000 个 KeyValues 项限制解析；本地化最多读取 64 个直接位于 `resource` 的文本文件、合计 8 MiB，并只保留最多 20000 个显示令牌。海报引用不能离开同一 VPK 的 `materials` 虚拟路径，VTF 正文最多 32 MiB且仅接受单帧、非立方体、最多 4096×4096/1600 万像素的受支持纹理格式，转换结果固定为最多 1280×720、1 MiB JPEG。Control 再次解码校验 JPEG 后才保存，海报接口继续按地图所属节点 read 权限授权；网页内置图片仅作为无海报或解码失败时的静态回退。备份会包含 Workshop 目录中的地图 VPK，并继续校验逐文件 SHA-256；恢复到已有相同地图硬链接时只复用校验一致的内容，避免改写内容寻址对象。删除要求无已知分配且实际链接计数符合注册表，异常或部分失败保留逻辑记录供校验/重试。
- 非 Workshop VPK/SMX 历史快照保存在 Agent 数据目录的哈希命名专用子目录，每个目标最多 3 个。专用版本列表不返回内部 Agent 存储定位符，通用任务响应也会递归移除这些定位符；回退再次校验实例、包、目标路径和 SHA-256，仅允许标准 VPK/SourceMod 插件目录中的普通文件，并在失败时恢复被替换版本。Workshop 当前不提供版本回退。
- 普通 URL 包只允许 HTTPS，限制重定向，并对每次解析/连接拒绝环回、链路本地和私网地址以缓解 SSRF。AlliedModders 官方包另外限制页面、仓库和资产主机。Workshop 合集与项目详情请求只能由代码构造为固定 Valve HTTPS URL，禁止重定向、校验证书并限制响应大小；为支持受限网络，它们可以使用节点管理员为 Agent 进程配置的系统 HTTPS 代理，但用户输入不能改变主机、路径或代理。详情标题视为不可信输入，生成 VPK 名称前删除点号、路径/Windows 保留字符和控制字符、收敛空白并限制 UTF-8 字节长度，最终目标仍通过实例根内的 no-follow 提交。
- 通知 Webhook 只接受无凭据、查询或片段的 HTTPS URL，禁止代理和重定向，并使用 `HMAC-SHA256(timestamp + "." + body)` 签名。配置时会拒绝直接写入的环回、私网、链路本地、组播、未指定地址及 IPv4 CGNAT `100.64.0.0/10`；拨号时重新解析 DNS、过滤同类地址并直接连接获准公网地址，降低 DNS 重绑定和出站 SSRF 风险。

- 包下载同时保留 10 分钟单源总时限和 30 秒读取空闲时限。只要 TCP/TLS 连接连续 30 秒没有交付任何新数据，Agent 就关闭该连接并进入下一个固定候选；持续有数据的慢速传输不会因空闲时限被中断，临时文件仍按失败路径清理。
- 官方 SourceMod/Metamod 安装会让固定 HTTPS 服务 `api.country.is` 与 `api.ip.sb` 看到 Agent 的公网出口 IP，以决定候选源顺序；请求不携带节点 ID、实例 ID、凭据或待下载包信息，响应也不保存或记录。两个请求并行、各自最多 4 秒，禁用代理和重定向，并在拨号时继续拒绝私网、环回、链路本地、组播与 CGNAT 地址。只有两个有效国家代码一致且均非 `CN` 时才使用官方源优先；返回 `CN`、任一失败或冲突均使用镜像优先。属地结果只改变顺序，不放宽固定镜像白名单、GitHub 官方 SHA-256/大小复核或其他下载边界。

## 进程、日志和备份

- 外部运行进程导入后不凭未知 PID 获得控制。外部实例受控重启可接收只写的 `existing_rcon_password`；中心在任务中加密并从 API/事件视图清除，Agent 仅用它请求旧进程 `quit`。未提供或 RCON 失败时，只有 PID 与实例内可执行路径重新匹配才允许强制接管。接管不会生成或注入密码配置；后续 RCON 使用中心端保存且应与 `server.cfg` 一致的凭据。启动/重启任务不能覆盖已登记的可执行文件、参数或环境；Agent 只允许实例根中的平台固定 `srcds` 文件名并重新校验参数。进程只继承系统路径、区域设置、临时目录等受限环境变量，且 `HOME`/`USERPROFILE` 被指向实例目录，避免继承 Agent 注册凭据或控制平面秘密。Windows 进程先以 `CREATE_SUSPENDED` 和隐藏的新控制台创建；Windows 只为空的标准输入句柄初始化控制台输入，输出和错误继续进入受限实例日志。Agent 仅把 SRCDS 固定的控制台输入初始化失败文本识别为进程降级原因，不把其他可控游戏日志文本提升为管理指令。进程加入带整树终止策略的 Job Object 后才恢复，创建、分配或恢复失败会终止仍挂起的进程。Linux 使用进程组管理子进程树。
- 游戏端口和非零 SourceTV 端口在同一节点共享数据库唯一预留表；立即事务中的 Go 端口扫描与数据库唯一索引共同阻止并发创建或跨字段修改造成重复预留。游戏端口只能在实例停止时修改：Control 在持久任务期间保留旧端口并通过独立表预留新端口，双向 SQLite 触发器使创建与待变更预留也互斥；Agent 再次拒绝活动进程的端口变化，任务成功才原子切换正式预留，失败或取消释放新预留。
- 停服优先向本机 RCON 发送 `quit`；超时后只结束 Agent 跟踪且进程身份匹配的树。Agent 单独持久化期望运行状态和自动重启策略，重启恢复前重新校验路径、参数与端口；显式停止不会被恢复。自动重启包含崩溃循环限制并触发通知。
- Agent 的 A2S 与 RCON 客户端只连接本机回环地址或 Agent 当时实际拥有的网卡 IP，并在这些本机地址中重试以兼容只绑定具体网卡的 SRCDS。Agent 还会有界解析一次自身主机名，但解析结果仍必须是回环地址或与当前网卡地址相同后才能成为候选，以覆盖 Linux/WSL 的 `127.0.1.1` 主机名回环且不扩大网络边界；实例通配绑定地址、Control 任务中的任意 host 值、恶意 DNS 结果或节点公开地址都不能把探测变成远端网络/云元数据请求。启动健康检查先并发确定实际响应 A2S 的安全本机地址，再只向同一地址发起 RCON，防止多网卡或不可达 IPv6 候选耗尽整个检查预算。安装后的 SourceMod/Metamod 版本校验和 SourceMod 插件回退校验同样先确定 A2S 实际响应地址，再只对该地址发送一次只读 RCON 命令。其他 RCON 操作一旦连到监听器但认证或协议失败就不再换地址重试。对外状态页和玩家连接地址单独使用管理员显式设置的节点 `public_address`（或安全的实例非通配 host）进行投影，不参与 Agent 的 A2S/RCON 目标选择。
- 日志保存在节点，当前最多为 100 MiB × 20 段。Agent 启动时及此后每小时清理超过 7 天的已关闭轮转段和停止实例当前段；运行中当前段保留到轮转。清理只接受严格命名的直属普通文件，拒绝符号链接/重解析点。搜索最多 1000 行/384 KiB，下载单块最大 1 MiB。不要把日志接口当作长期归档系统。
- 备份只保存节点本地的可移植配置/插件目录，清单记录平台和逐文件 SHA-256；旧版可能含密码的 `left4dead2/cfg/l4d2panel.cfg` 明确排除，用户维护的 `server.cfg` 正常纳入备份。v3 清单的启动快照采用无秘密专用结构，并只记录已分配地图的 ID、聚合哈希、名称和 BSP 引用，不复制硬链接 VPK；v1/v2 继续兼容。恢复先验证完整归档；v3 仅从目标节点现有健康地图按 ID、再按哈希恢复分配，缺失只产生警告，且来源启动地图属于缺失对象时保留目标启动地图。Control 对 Agent 返回的无秘密启动投影再次验证，并以任务 ID 幂等更新当前配置。目录同步不是原子交换，任何失败都会尝试用含地图引用的预恢复检查点以及捕获的 registry/旧版遗留配置恢复原状态。
- 备份元数据列表需要目标实例 `read`，但创建和消费备份正文下载任务需要该实例 `operate`；正文分块仍为一次性加密暂存。
- 每日备份按 ISO 周生成至多一个周副本；Control 以确定性 ID 投影周副本，并在同一事务删除 Agent 已裁剪路径的元数据。备份、周副本、恢复归档和恢复前检查点的 Agent 本地定位符会从任务、API 与事件视图中按任务类型递归移除；恢复归档定位符在 SQLite 中使用 AES-GCM 密文保存，仅在向 Agent 派发时解封。
- 实时 WebSocket 事件日志只保留 30 天且持久化时压缩任务数据；单 Control 进程将持久事件提交与进程内广播串行化以保持游标顺序，瞬时事件不受该锁影响。它不替代不可编辑审计记录，也不应作为长期合规归档。
- 包版本快照同样只存在节点本地；节点磁盘损坏会同时丢失这些回退点，它们不是外部备份。
- 隔离删除把实例移动到白名单根的 `.quarantine`，Control 只保存根索引和严格 basename，不保存/返回任意清理路径。七天是不可绕过的最短保留期，且 Control 从收到结果时起计时，旧任务重放或伪造的过早名称时间戳不能缩短它；Agent 不做后台永久删除。到期后仍需节点管理员使用交互式会话完成两阶段确认。确认令牌仅返回一次、5 分钟有效、只存 SHA-256，并绑定用户和隔离条目；消费令牌与创建 `purge_quarantine` 任务位于同一事务，匹配 Idempotency-Key 的重放只返回原任务。Agent 再次校验时间戳、配置根、直属目录与整棵树中的符号链接/重解析点，拒绝任意路径、未知名称和未到期条目。确认和永久清理请求保留审计记录；成功清理不可恢复。
- 用户任务的幂等映射除用户和键外，还用部署主密钥对规范化目标、动作、正文及版本计算 HMAC-SHA256。指纹在 RCON 命令、密码、私有 URL、上传正文和确认令牌加密或散列前生成，但数据库只保存 64 字符十六进制 HMAC；不同请求和旧版无指纹记录均安全冲突。内部无秘密调度使用相同作用域结构的普通 SHA-256。已派发任务取消后的 `cancel_pending` 只允许 Agent 提交一次最终终态，普通 canceled 任务不能复活。
- 放弃跨节点上传是专用 DELETE 接口而非通用 action：必须具备实例 `operate` 权限并提供非空幂等键，不接受请求正文。事务在标记会话过期前排除活跃、取消待确认及尚未投影的分块/恢复任务；Agent 任务只携带 UUID 并调用受限暂存清理，不接受路径或 Shell。任务 API、事件和审计不暴露节点暂存路径或任意 Agent 诊断字段。

## 通知和公开状态

- SMTP 必须宣告 STARTTLS，并要求 TLS 1.2+。Webhook 带时间戳和签名，接收方应限制时间偏差、常量时间比较签名并去重通知 ID。
- 外部投递最多尝试 6 次，保留响应码/错误；秘密不会出现在投递列表。手工重试仅适用于 `failed` 或 `pending` 投递。
- 公开状态页只返回显式启用实例的名称、状态、地图、模式、人数、启动时间和连接地址。地址来自管理员设置的节点 `public_address`，或非通配的实例 host；不返回玩家身份、节点路径、封禁、RCON 或秘密。

## 生产检查清单

- 使用真实域名和受信任 TLS 证书，保持 `COOKIE_SECURE=true`，只配置必要的 `TRUSTED_PROXIES`。
- 生成独立的 32 字节主密钥；启动后立即在可信网络中通过 `/setup` 建立首个所有者，再对公网开放服务。
- SQLite 数据库、WAL、SHM 与备份都包含敏感数据，只能放在中心本机磁盘和受限权限目录，禁止放到 NFS/SMB/CIFS；限制中心和节点的出站网络，通知 Webhook 目的地使用明确允许清单。
- 为所有所有者启用 TOTP，并离线保存恢复码；API Token 使用最小权限、最小资源范围和较短有效期。
- 定期检查审计、通知投递失败、离线节点、磁盘阈值和第三方包来源；在节点外另存关键备份。
- 发布前在每个正式支持平台使用真实 SteamCMD/App 222860 验证安装、A2S、RCON、更新、恢复和进程树。自动化构建成功不代表 Valve 服务或真实主机验收完成。
