# 安全边界与威胁模型

## 信任边界

- Control、本机 SQLite、Caddy 和部署主密钥位于可信中心环境。单个 Control 进程是授权和派发决策点。
- Windows 原生中心端把 Control 与 Caddy 放在独立虚拟服务账号下。Control 仅回环监听，SQLite 不监听网络端口，只有 Caddy 入口加入防火墙；ProgramData 中的秘密配置和 SQLite 目录禁用 ACL 继承，只允许 Administrators、SYSTEM 和 Control 服务 SID。服务命令行只出现配置路径，不出现主密钥。
- Agent 是节点上唯一拥有实例文件与受管游戏进程操作权的组件。面板管理员不会因此获得操作系统 Shell；Agent 只接受固定任务类型和经过校验的参数。
- RCON 可执行游戏命令，因此属于高权限游戏接口。命令通过权限检查，敏感形态在审计/任务视图中脱敏，明文命令只以部署主密钥加密后排队。
- VPK、SMX、SourceMod 插件和原生扩展是不可信内容。特别是 `.dll/.so` 会在游戏进程权限内执行，只允许管理员安装，第三方原生包还必须显式确认风险。
- 当前同一节点的 Agent 和全部 srcds 进程共用一个低权限服务账号，没有每实例 OS 身份或进程沙箱。PathGuard 约束的是 Agent 接口，不能阻止已在游戏进程内执行的恶意原生扩展读取该账号可访问的其他实例数据；相互不信任的实例必须使用不同主机或额外的 OS 级隔离。
- 节点本身被攻陷后，Agent 凭据、该节点实例和本地备份均不再可信；节点隔离不是对恶意主机管理员的沙箱。

## 用户认证和授权

- 密码使用 Argon2id；登录按“来源 IP”和“来源 IP + 规范化用户名”分别限速，5 分钟窗口内组合上限 8 次、IP 总上限 32 次。
- 首次启动不要求环境变量携带引导密码。仅在数据库没有用户时，`/setup` 可用短期 HttpOnly/SameSite=Strict 引导 Cookie、独立 CSRF 令牌和专用限速创建首个所有者；SQLite 立即事务与事务内计数确保并发提交只有一个成功。创建后入口立即失效。
- 浏览器会话 Cookie 为 HttpOnly、SameSite=Strict；生产环境必须启用 Secure。所有非安全方法还需匹配 `X-CSRF-Token`。
- TOTP 秘钥用 `MASTER_KEY` 加密。启用 TOTP 时返回 10 个恢复码且只显示一次；数据库只保存加域哈希，每个恢复码通过事务原子消费一次。
- API Token 以 `l4d2p_` 开头，明文只在创建响应返回，数据库只保存 SHA-256 摘要。Token 必须有未来过期时间，权限为 `read/operate/manage`，可限定到节点或实例，且不能超出创建者绑定。
- Bearer API Token 不受 CSRF 影响，但不能调用注销、TOTP、API Token 管理或团队账号管理等要求交互式会话的接口；即使由所有者签发，也不能执行 `root_security` 操作。
- 团队账号列表、创建、密码重置、禁用和角色绑定修改全部要求全局所有者的交互式会话。更改密码、禁用账号或替换角色绑定会撤销目标账号的所有现有会话和 API Token。引导所有者不可禁用/降级，系统始终要求至少一个启用的全局所有者。

## RBAC

角色权限从高到低：

- 所有者：全部资源以及根安全设置，可管理其他所有者。
- 管理员：节点和实例管理、包安装及通知渠道；不能查看或管理团队账号，也不能修改根安全设置。
- 操作员：启停、RCON、玩家、配置、备份、恢复、更新和计划任务；不能注册/删除节点、删除实例、重装或安装高风险组件。
- 观察者：只读。

绑定可以是全局、某节点或某实例。节点绑定自动覆盖该节点内实例；实例绑定不授予节点级管理。Control 在列表、单资源、任务、指标、通知、审计和 WebSocket 事件上都执行资源过滤，而不是只依赖前端隐藏按钮。在线事件流使用当前主体快照做内存过滤；登出、Token 吊销、账号禁用、密码或绑定变更会递增授权代际并在通知后的下一帧前重验，另每 1 秒从数据库兜底重验数据库提交到进程内通知之间的极短调度窗口、到期和进程外变更。历史或未知且没有明确节点/实例归属的事件对受限主体一律隐藏。

任务正文和结果只有对该任务目标节点/实例具备 `operate` 权限时才返回；在目标资源只有 `read` 的绑定不会因为用户在其他资源是操作员而绕过脱敏。加密秘密字段在任何角色的任务视图中都不会返回。

## 节点身份和传输

- 注册令牌由 CSPRNG 生成、数据库只存摘要、有效期 1 分钟至 7 天且成功使用后立即消费。
- 节点长期凭据数据库只存摘要，可由管理员轮换或随节点删除吊销。轮换会断开旧连接并让节点离线，管理员需安全更新节点配置。
- 除 localhost 开发外，Agent 配置拒绝非 TLS 中心 URL。节点通过 HTTPS/WSS 主动出站连接，不开放面板管理端口。
- Control 在持久化或发布前批量验证心跳、指标和日志中的每个实例都属于当前 WSS 节点；未知或跨节点实例会拒绝整条消息。成功归属按连接缓存 2 秒且上限 1024 项，同一实例并发 miss 合并；失败不缓存，实例删除成功后立即清除缓存，所以数据库查询量受实例数和 TTL 限制而不随日志行数增长。`job_update` 必须匹配任务节点和实例，嵌套结果中的 `instance_id` 也不能指向其他实例。入站心跳、指标、日志、进度和终态结果分别设有消息/批量上限，并校验状态、数值、时间窗口与日志流；重复或高频进度会被丢弃/合并，终态不会被节流。
- Agent 配置原子写入；Unix 权限为 0600。Linux 安装器以专用无登录账号运行并启用 systemd `NoNewPrivileges`、空 capabilities、只读系统目录和明确写目录；Windows 安装器使用虚拟服务账号和受限 ACL。
- Caddy 提供 HSTS 等外层响应头；Control 还设置 CSP、frame deny、MIME sniffing 禁止和权限策略。只有配置的可信代理网段可影响客户端 IP。

## 秘密和任务数据

- `MASTER_KEY` 必须解码为正好 32 字节，用于加密 TOTP、RCON、服务器密码、SMTP/Webhook 秘密，以及任务中的 RCON 命令、外部实例旧 RCON 密码、带查询参数的下载 URL、备份/恢复归档定位符、文件/包上传正文、日志查询关键字和传输正文。
- 计划任务的 payload 以普通 JSON 保存，因此创建接口只允许 `start/stop/restart/update/validate/backup/broadcast`，并按动作复制已知字段；任意 RCON、URL、文件正文和包安装等秘密/高风险动作不能进入计划表。
- RCON、SMTP/Webhook 密钥和服务器密码不会通过普通资源列表返回。API Token、恢复码、注册令牌和节点凭据只存摘要。
- 文件内容与日志/备份分块虽然经过 Control，但不以明文持久化。日志搜索结果和下载块在读取后从任务结果删除；再次读取返回 `410 Gone`。
- 跨节点备份上传要求顺序 offset、每块 SHA-256、末块整包大小/SHA-256 和分块必填幂等键。单块解码上限 1 MiB、单会话上限 20 GiB且 Control 会话默认 24 小时，每个成功块只续期 24 小时；正文在 Control 任务中以主密钥加密并于终态清除，只暂存在目标 Agent 的受限数据目录。Agent 默认限制为每节点 32 个会话和 64 GiB 预约总量。首次可信分块在节点上传互斥内先用临时文件、刷盘和原子改名写入严格 JSON、权限 `0600` 的预约 sidecar，后续分块必须与其中的整包大小/SHA-256 完全一致；旧版无 sidecar 的 `.part/.zip` 在可信续传升级前按 20 GiB 保守预约。上限同时核算所有会话 `expected_size`、sidecar/临时元数据和未知常规文件，磁盘检查覆盖全部未完成预约并保留 5 GiB 余量，检查失败发生在任何 `.part` 变更前。Agent 对无活动未完成 `.part` 使用约 25 小时保留期，完整 `.zip` 使用 48 小时保留期；完整校验与每次恢复尝试都会续租完整会话。完成、续租、删除和清理按 UUID 将 `.part/.zip`、sidecar 和原子临时文件成组协调，覆盖 Control 失败后续期的 24 小时无重传重试窗口且不会遗留不计费文件。会话/API 不返回 staging 路径，过期上传由两端清理；只有完整 ready 会话可进入现有停服、检查点和归档验证恢复流程。同一恢复键始终重放原任务；失败或取消后会话续期 24 小时，新键可无重传重试。
- Agent 的受限数据目录 journal 会保留任务终态和原始结果，直到 Control 已成功持久化、应用并发布对应事件后返回 `job_ack`；ACK 丢失时结果保留并在重连后重放，收到 ACK 后原子删除。因此 Agent 数据目录与本地节点备份一样属于敏感节点数据，必须维持服务账号专用权限。
- `MASTER_KEY` 丢失会导致已加密秘密不可恢复；密钥泄露会破坏这些秘密的机密性。应在密码管理器中备份密钥，轮换前需要专门迁移流程，不能直接替换环境变量。
- Windows MSI 固定使用 `%ProgramData%` 本机 SQLite。普通卸载刻意保留数据库、WAL、SHM、主密钥和证书；彻底清理工具要求精确确认短语、精确默认路径且两个中心服务已删除。升级先停止服务并通过 SQLite Backup API 创建检查点，失败时保留原数据库、检查点和恢复说明。

## 文件、归档与下载

- `PathGuard` 先做词法归一化，再验证真实路径仍在配置根内；符号链接和 Windows 重解析点不能用来逃逸。文件管理的列举、读取、原子写入和删除还使用目录句柄相对操作消除检查后替换窗口：Linux 以 `openat2/openat`、`O_NOFOLLOW` 和受限解析逐级打开，Windows 以 `NtCreateFile`、`RootDirectory`、`OBJ_DONT_REPARSE` 和不共享删除的句柄固定目录对象；旧内核回退也从 `/` 逐级 no-follow 打开，不退化为再次按绝对路径访问。相同原语用于外部 ZIP/tar、Workshop、单文件 VPK/SMX/native 安装、版本快照/回退、模组启停移动、备份恢复 overlay/extras 清理和含秘密生成配置；内容在提交前验证精确大小及可用的 SHA-256。Windows 另拒绝 ADS、设备名和特殊 Win32 路径组件。启动参数以数组传给 `exec`，不经 Shell。
- 备份创建与 VPK 冲突检测仍会对实例内目录做只读路径遍历，Agent 专属 staging/备份保留策略也会按自身数据目录清理名称；这些路径不承担向实例落盘。不受信任归档不能在 staging 创建链接，所有后续实例 mutation 会再次由句柄边界约束。同一节点的 Agent 与游戏进程共享低权限服务账号，因此本设计不是抵抗该账号下任意恶意本机进程的每实例 OS 沙箱；不互信的原生插件应部署到不同主机或服务账号。
- 安装发现只在配置的实例根内做有界、只读、非链接扫描，返回根索引与相对路径；它不会枚举任意系统目录。扫描到的外部运行进程必须在导入和受控重启时再次核对可执行路径，不能仅凭 PID 接管。
- 文件 API 只开放 `cfg/addons/logs` 白名单目录；目录列表需要实例 `read`，正文读取及写/删需要 `operate`。单文件上限 8 MiB，不允许递归删除目录，也不能修改生成的 `l4d2panel.cfg` 或 `.bat/.cmd/.com/.dll/.dylib/.exe/.ps1/.sh/.smx/.so/.vdf/.vpk` 可执行/加载关键格式；这些格式只能走包管理流程。SHA-256 前置条件用于检测并发覆盖。
- 结构化配置会在 Control 和 Agent 两端拒绝 CVar 映射中的 `rcon_password`、`sv_password`；这两个值只能从中心加密秘密存储注入生成文件。
- ZIP/TAR 解包限制文件数、单文件/展开总大小和压缩比，拒绝绝对路径、`..`、设备文件和链接。VPK v1/v2 验证目录树大小/项数、安全 UTF-8 相对路径、节区边界、终止符、重复/重叠条目和逐项 CRC32；单文件安装拒绝引用外部分卷。v2 公钥/签名区当前只验证结构长度，不执行密码学签名验证，因此不能据此信任发布者身份。安装、Workshop 批次、回退和重新启用都会把虚拟内容路径与全部已启用 VPK 做不区分大小写的交叉冲突检查；同包替换只排除自身旧清单，发现其他重叠即拒绝。操作仍校验完整文件 SHA-256 与目标文件冲突。
- 非 Workshop VPK/SMX 历史快照保存在 Agent 数据目录的哈希命名专用子目录，每个目标最多 3 个。专用版本列表不返回内部 Agent 存储定位符，通用任务响应也会递归移除这些定位符；回退再次校验实例、包、目标路径和 SHA-256，仅允许标准 VPK/SourceMod 插件目录中的普通文件，并在失败时恢复被替换版本。Workshop 当前不提供版本回退。
- 普通 URL 包只允许 HTTPS，限制重定向，并对每次解析/连接拒绝环回、链路本地和私网地址以缓解 SSRF。AlliedModders 官方包另外限制页面、仓库和资产主机。Workshop 合集 API 也使用固定 Valve 主机。
- 通知 Webhook 只接受无凭据、查询或片段的 HTTPS URL，禁止代理和重定向，并使用 `HMAC-SHA256(timestamp + "." + body)` 签名。配置时会拒绝直接写入的环回、私网、链路本地、组播、未指定地址及 IPv4 CGNAT `100.64.0.0/10`；拨号时重新解析 DNS、过滤同类地址并直接连接获准公网地址，降低 DNS 重绑定和出站 SSRF 风险。

## 进程、日志和备份

- 外部运行进程导入后不凭未知 PID 获得控制。外部实例受控重启可接收只写的 `existing_rcon_password`；中心在任务中加密并从 API/事件视图清除，Agent 仅用它请求旧进程 `quit`，随后写入面板新 RCON 配置。未提供或 RCON 失败时，只有 PID 与实例内可执行路径重新匹配才允许强制接管。启动/重启任务不能覆盖已登记的可执行文件、参数或环境；Agent 只允许实例根中的平台固定 `srcds` 文件名并重新校验参数。进程只继承系统路径、区域设置、临时目录等受限环境变量，且 `HOME`/`USERPROFILE` 被指向实例目录，避免继承 Agent 注册凭据或控制平面秘密。Windows 进程先以 `CREATE_SUSPENDED` 创建，加入带整树终止策略的 Job Object 后才恢复；创建、分配或恢复失败会终止仍挂起的进程。Linux 使用进程组管理子进程树。
- 游戏端口和非零 SourceTV 端口在同一节点共享数据库唯一预留表；立即事务中的 Go 端口扫描与数据库唯一索引共同阻止并发创建或跨字段修改造成重复预留。
- 停服优先向本机 RCON 发送 `quit`；超时后只结束 Agent 跟踪且进程身份匹配的树。Agent 单独持久化期望运行状态和自动重启策略，重启恢复前重新校验路径、参数与端口；显式停止不会被恢复。自动重启包含崩溃循环限制并触发通知。
- Agent 的 A2S 与 RCON 客户端只连接本机回环地址：实例通配绑定地址、Control 任务中的 host 值或节点公开地址都不能把它们变成任意网络/云元数据探测器。对外状态页和玩家连接地址单独使用管理员显式设置的节点 `public_address`（或安全的实例非通配 host）进行投影，不参与 Agent 的 A2S/RCON 目标选择。
- 日志保存在节点，当前最多为 100 MiB × 20 段。Agent 启动时及此后每小时清理超过 7 天的已关闭轮转段和停止实例当前段；运行中当前段保留到轮转。清理只接受严格命名的直属普通文件，拒绝符号链接/重解析点。搜索最多 1000 行/384 KiB，下载单块最大 1 MiB。不要把日志接口当作长期归档系统。
- 备份只保存节点本地的可移植配置/插件目录，清单记录平台和逐文件 SHA-256；含 RCON/服务器密码的生成文件 `left4dead2/cfg/l4d2panel.cfg` 明确排除。v2 清单的启动快照采用无秘密专用结构，无法表示 RCON/服务器密码，并对标识符、CVar、参数数量/长度、危险或冲突参数、平台和路径大小写碰撞做边界校验；旧 v1 清单只兼容文件数据。恢复先验证完整归档。跨平台时先安装和验证目标平台 Metamod/SourceMod，再跳过来源原生文件并最终覆盖来源可移植数据，防止官方默认 configs 覆盖用户配置；错误平台的既有二进制不会被保留。v2 用来源启动资料加目标加密秘密生成配置，Control 对 Agent 返回的无秘密投影再次验证并以任务 ID 幂等写入配置版本；v1 保留目标启动资料。目录同步不是原子交换，任何失败都会尝试用预恢复检查点以及捕获的 registry/生成配置恢复原状态。
- 备份元数据列表需要目标实例 `read`，但创建和消费备份正文下载任务需要该实例 `operate`；正文分块仍为一次性加密暂存。
- 每日备份按 ISO 周生成至多一个周副本；Control 以确定性 ID 投影周副本，并在同一事务删除 Agent 已裁剪路径的元数据。备份、周副本、恢复归档和恢复前检查点的 Agent 本地定位符会从任务、API 与事件视图中按任务类型递归移除；恢复归档定位符在 SQLite 中使用 AES-GCM 密文保存，仅在向 Agent 派发时解封。
- 实时 WebSocket 事件日志只保留 30 天且持久化时压缩任务数据；单 Control 进程将持久事件提交与进程内广播串行化以保持游标顺序，瞬时事件不受该锁影响。它不替代不可编辑审计记录，也不应作为长期合规归档。
- 包版本快照同样只存在节点本地；节点磁盘损坏会同时丢失这些回退点，它们不是外部备份。
- 隔离删除把实例移动到白名单根的 `.quarantine`，Control 只保存根索引和严格 basename，不保存/返回任意清理路径。七天是不可绕过的最短保留期，且 Control 从收到结果时起计时，旧任务重放或伪造的过早名称时间戳不能缩短它；Agent 不做后台永久删除。到期后仍需节点管理员使用交互式会话完成两阶段确认。确认令牌仅返回一次、5 分钟有效、只存 SHA-256，并绑定用户和隔离条目；消费令牌与创建 `purge_quarantine` 任务位于同一事务，匹配 Idempotency-Key 的重放只返回原任务。Agent 再次校验时间戳、配置根、直属目录与整棵树中的符号链接/重解析点，拒绝任意路径、未知名称和未到期条目。确认和永久清理请求保留审计记录；成功清理不可恢复。
- 用户任务的幂等映射除用户和键外，还用部署主密钥对规范化目标、动作、正文及版本计算 HMAC-SHA256。指纹在 RCON 命令、密码、私有 URL、上传正文和确认令牌加密或散列前生成，但数据库只保存 64 字符十六进制 HMAC；不同请求和旧版无指纹记录均安全冲突。内部无秘密调度使用相同作用域结构的普通 SHA-256。已派发任务取消后的 `cancel_pending` 只允许 Agent 提交一次最终终态，普通 canceled 任务不能复活。
- 放弃跨节点上传是专用 DELETE 接口而非通用 action：必须具备实例 `operate` 权限并提供非空幂等键，不接受请求正文。事务在标记会话过期前排除活跃、取消待确认及尚未投影的分块/恢复任务；Agent 任务只携带 UUID 并调用受限暂存清理，不接受路径或 Shell。任务 API、事件和审计不暴露节点暂存路径或任意 Agent 诊断字段。

## 通知和公开状态

- SMTP 必须宣告 STARTTLS，并要求 TLS 1.2+。Webhook 带时间戳和签名，接收方应限制时间偏差、常量时间比较签名并去重通知 ID。
- 外部投递最多尝试 6 次，保留响应码/错误；秘密不会出现在投递列表。手工重试仅适用于 `failed` 或 `pending` 投递。
- 公开状态页只返回显式启用实例的名称、状态、地图、模式、人数、启动时间和连接地址。地址来自管理员设置的节点 `public_address`，或非通配的实例 host；不返回玩家身份、节点路径、封禁、RCON 或秘密。

## 生产检查清单

- 使用真实域名和受信任 TLS 证书，保持 `COOKIE_SECURE=true`，只配置必要的 `TRUSTED_PROXIES`。
- 生成独立的 32 字节主密钥；启动后立即在可信网络中通过 `/setup` 建立首个所有者，再对公网开放服务。
- SQLite 数据库、WAL、SHM 与备份都包含敏感数据，只能放在中心本机磁盘和受限权限目录，禁止放到 NFS/SMB/CIFS；限制中心和节点的出站网络，通知 Webhook 目的地使用明确允许清单。
- 为所有所有者启用 TOTP，并离线保存恢复码；API Token 使用最小权限、最小资源范围和较短有效期。
- 定期检查审计、通知投递失败、离线节点、磁盘阈值和第三方包来源；在节点外另存关键备份。
- 发布前在每个正式支持平台使用真实 SteamCMD/App 222860 验证安装、A2S、RCON、更新、恢复和进程树。自动化构建成功不代表 Valve 服务或真实主机验收完成。
