# 实例操作并发优化

## 目标与边界

减少实例占用造成的重复点击，让互不影响的准备工作重叠执行。继续保持每实例一个写任务、每游戏安装一个维护任务和节点 SteamCMD 并发上限；取消待确认及终态待投影仍持有写锁。跨实例普通任务已经并行，不增加全局串行队列。

## 第一阶段：已实现

1. 插件压缩包预检不再占 Control 的实例写锁，与 Agent 已有的只读分类一致。下载、解包和计划生成可与实例写任务并行；每实例最多一个活动预检，避免重复点击产生大量并行解包。预检只是当时的诊断，正式安装继续在写锁内重新校验文件、归属和接管条件；第六阶段增加短期准备结果复用。
2. 批量启用、停用、删除在收到明确的实例占用拒绝后等待当前条目，不再把整批快速标为失败。等待以 750 毫秒开始、指数退避到 3 秒，每项最多等待 10 分钟；收到任务 ID 后仍等待该任务终态及写锁释放，才提交下一项。
3. 409 保留 `conflict` 错误码，实例占用额外返回 `reason=instance_busy` 和 `blocking_job_id`。前端仅重试这种明确未创建任务的拒绝，同一条目复用原幂等键及原请求内容。普通 409、权限拒绝、网络断开和服务端错误不自动重试。每次重试都重新经过服务端权限、状态、依赖检查。
4. 停止或离开页面后不再提交剩余条目；已经提交的任务继续由任务中心管理。等待发生在当前页面，不是持久服务端队列；刷新不恢复未提交操作。
5. 新增前向迁移 019，保留任务 ID、外键、幂等记录及写锁状态语义。两个锁分类字段仍为生成列，写锁继续使用唯一部分索引；使用虚拟生成列避免重建被多张业务表引用的 jobs 表。旧迁移不修改。

模组扫描会把磁盘发现结果写入 Control 包清单。现有防陈旧结果逻辑只覆盖部分并发变更；第一阶段保留其 Control 写锁（第五阶段已解除），避免删除、停用、恢复与延迟扫描结果交错导致记录复活。

## 第二阶段：已实现单文件并行准备、串行安装

单文件 VPK、SMX、原生 DLL/SO 的 HTTPS/上传已支持显式“预下载，稍后安装”。准备任务不占实例锁，每节点并行 2 个，共享 8 路下载上限；最多 16 个暂存槽，单个 HTTPS 文件不超过 512 MiB，上传不超过 100 MiB，额外保留 1 GiB 磁盘余量。准备结果持久绑定节点、实例、摘要、大小、安全名称及 1 小时有效期，刷新和 Agent 重启后可继续使用。

- 专用准备/安装/丢弃接口均使用 `packages.install`，按 `prepared_packages_v1` 协商；原始来源和上传正文继续加密、脱敏及终态清除。
- 迁移 020 保留每实例一个写任务，将准备/丢弃豁免，并约束每个准备 ID 只能有一个消费意图。原幂等请求始终重放原任务，安装失败或取消须重新准备。
- 安装取得现有写锁后重新核对归属、有效期、摘要、大小和目标文件；VPK/SMX 复用版本管理与失败回滚，原生扩展使用安全原子复制并确认代码风险。准备阶段不触碰实例文件。
- 网页支持刷新后恢复准备列表、单个或依次安装、忙碌等待与停止后续提交。初版安装等待仅存在当前页面；下述持久队列阶段已替换此行为。取消、崩溃未完成、领取后及过期暂存按安全固定路径回收。

## 第三阶段增量：已接入 QQ 闪传单文件准备

- VPK、SMX、DLL/SO 的 QQ 闪传分享可显式预下载，沿用同一准备容量、并发和有效期，不占实例写锁；准备完成后使用原逐项安装流程。
- 新增 `prepared_qq_flash_v1` 能力门控，旧 Agent 不接收此类准备。目录元数据须证明恰好一个匹配类型的文件且不超过 512 MiB，多文件及归档保留原导入流程。
- 文件名来自验证后的分享元数据，正文直接进入原暂存槽；分享路径整体加密，安装仍校验归属、摘要、大小、VPK 结构及风险确认。

## 第四阶段：已实现预下载包的持久安装队列

- 一次提交 1–16 个就绪包，等待清单单独持久化，协调任务不占写锁、不派发节点；每实例最多一个活动队列。
- 在立即事务中重新授权并验证有效期、目标归属及实例状态，只创建一个安装子任务；等待其终态和取消/投影屏障释放后再推进。首次派发再次检查，已派发任务保留 journal/ACK 协议。
- 关闭浏览器或中心端重启后恢复。权限依据原用户当前绑定，API Token 还校验原 ID、范围、撤销和有效期。退出交互会话不撤销已提交的用户委托。
- 任一失败停止后续安装；停止队列释放未提交项，已创建的安装任务继续执行。页面恢复进度和停止入口不要求任务列表权限。
- 迁移 021 保持 generated-column 写锁分类和原消费唯一性；等待项另有唯一预留。旧立即安装 API 保留，不能消费已被等待清单预留的包。

## 第五阶段：已实现并行扫描及陈旧结果防护

- scan_packages 不占实例写锁，每实例一个独立扫描槽，保留取消确认与投影屏障。Agent 原只读实现和能力协议不变。
- 迁移 022 由触发器原子记录扫描代际；所有写任务、登记/整包文件清单和实例目标变更都会使旧扫描失效。有效性检查、登记和 applied/stale 标记在同一立即事务完成。
- 已处理投影重放不会再登记，避免删除/改名后记录复活；跳过整包拥有的路径。旧库扫描保留任务，但缺少快照的结果不再采用。
- 页面刷新后仍可查看扫描中、结果作废和新增登记数量；扫描中可继续安装，需要安装权限但不需要任务列表权限。

## 第六阶段增量：智能插件复用预检准备结果

- 智能插件本机上传及 QQ 闪传单归档，预检时可保留已展开的安全文件。安装命中同一节点、实例、实例路径、原始来源/上传摘要、路径编码及预览指纹时，直接重新检查这些文件，省去写锁内的重复下载和解包。
- 每节点最多 4 个缓存，单个沿用 5000 文件、512 MiB/文件、2 GiB 展开限制，开始准备起 1 小时内可领取一次。预检与单文件预下载共享 2 个准备槽和现有下载上限；保留最坏展开容量及磁盘余量。缓存满或剩余空间不足时仍可正常预检，正式安装回到原下载/解包路径。
- 缓存使用独立目录下的随机平面文件名，只信任当前 Agent 内存中的归属与清单。逐文件以 no-follow 打开并校验大小/摘要；正式安装重建当前目标状态、路径归属和完整指纹，继续要求接管/原生代码/运行中操作确认，提交时再核对摘要，失败沿用整批回滚。
- 消费、失败、过期及 Agent 重启遗留文件安全回收。Agent 重启后不恢复缓存，安装使用原归档重新检查；现有 API、能力协议及终态结果不变。此项是现有预检流程的透明优化，尚未成为持久预下载安装队列中的整包条目。

## 第七阶段增量：QQ 多文件及 VPK 归档的持久准备

- QQ 闪传中的多个 VPK 或仅包含 VPK 的 ZIP/7Z/RAR 现可预下载，准备不取得实例写锁；下载、解包和完整 VPK 校验复用原导入规则。
- 独立持久暂存清单绑定节点/实例/有效期与全部文件摘要，最多 4 个整包槽，每份最终 VPK 最多 2 GiB/1000 个、单文件 512 MiB；与单文件及智能预检共享两个执行槽。Agent 重启后恢复就绪记录，未完成、已领取和过期记录按固定平面路径安全回收。
- 通过 prepared_vpk_bundles_v1 协商接入原持久安装队列。可与单文件一起顺序安装，网页刷新显示文件数；旧 Agent 保留单文件入口，队列不会提前创建不兼容整包的写任务。
- 正式安装在写锁内复核整包与当前目标归属，全部 VPK 重新验证后不覆盖写入；失败回滚新增文件。Control 将最终投影逐项对照原准备清单，拒绝篡改路径或摘要等字段。现有数据库 schema、幂等和终态确认协议不变。

## 第八阶段增量：智能插件预检快照支持 Agent 重启恢复

- 智能插件本机上传/QQ 单归档的已完成预检输入现可持久恢复；延续四个槽、每份 2 GiB/5000 文件、单文件 512 MiB、共享两个准备执行槽及从开始准备起一小时有效期。第六阶段的重启后重新下载限制已解除。
- 专用新目录存放 UUID/序号推导的平面数据文件和有界清单；节点凭据以独立用途 HMAC 认证请求绑定、原预览指纹、有效期及全部输入清单。仅保存来源摘要，不保存来源正文、主机路径、旧目标或权限判断；旧版本不会误读新格式。
- 实例写入前先持久标记领取，重启不恢复已领取快照。消费时重建当前目标、归属及完整预检指纹，继续执行原生代码、接管、运行中确认和整批回滚。正文被篡改或目标变化时拒绝安装；缺失/无效清单、过期或凭据轮换时回到原归档验证流程。
- 未完成数据、已领取、过期及旧格式缓存按固定文件名 no-follow 回收。未改 Control API、能力协议或数据库 schema；此项完成预检输入的持久恢复，尚未把智能插件变成持久安装队列中的独立整包条目。

## 第九阶段增量：Workshop 持久准备与安装队列

- Workshop 项目/合集预下载不占实例写锁，保留固定 Valve 接口、匿名 SteamCMD App 550 和节点并发限制；同项目下载和快照复制互斥。沿用标题清洗及多文件稳定序号，不增加 VPK 内容验证或 512 MiB 限制。
- 就绪快照独立持久保存，最多四份、每份 8 GiB/1000 文件、合集最多 200 项，包含在 Control 十六个总准备槽内，与其他准备共享两个执行槽，一小时有效。Agent 重启后可继续安装；未完成、已领取和过期数据按固定文件名安全回收。
- 通过 prepared_workshop_v1 接入现有持久安装队列，前端支持刷新后加入和查看队列。安装重新核对清单及当前目标归属，持久领取后校验全部输入，再不覆盖写入并保留失败回滚；Control 逐项匹配原清单并事务投影。旧 Agent 保持队列等待，不创建写任务占锁。

## 第十阶段：第三方组件原归档持久准备与安装队列

- SourceMod/Metamod 的上传、HTTPS 和单文件 QQ ZIP/tar.gz 原归档支持并行预下载，复用两个准备任务上限、总计十六个槽、一小时有效期及已有来源保护；上传 100 MiB、HTTPS/QQ 512 MiB。
- 原归档在独立平面目录持久保存，刷新和 Agent 重启后可提交队列。此阶段提前完成下载与摘要，归档展开仍在安装环节；不声称已完成整包解包阶段的并行化。
- 消费时在立即事务中重读依赖、组件清单和文件归属；SourceMod 须先已有纳管启用的 Metamod 再提交队列。Agent 重新确认风险、RCON 和磁盘依赖，复用原组件安装、检查点、admins_simple.ini 保护、启动验证及失败回滚。
- 新能力 `prepared_extensions_v1` 单独协商，旧 Agent 不接收新任务，队列等待时不占写锁；终态绑定输入与验证结果后投影，保持取消/ACK 和终态屏障。
